## 6. Engineering rules

Apply these rules throughout implementation:

* TypeScript strict mode must remain enabled.
* Python code must be fully type-checked.
* Public functions and services must have clear contracts.
* Domain logic must be separated from framework and provider integrations.
* GitHub, GitLab, model providers, storage and sandbox runtimes must use adapter interfaces.
* External side effects must be idempotent.
* Long-running work must be resumable.
* Approval records must be bound to immutable artifact digests.
* No agent or model output may directly authorize an action.
* Repository content must be treated as untrusted input.
* Secrets must never be written to logs, prompts, patches, test snapshots or build artifacts.
* Database schema changes must use versioned migrations.
* Production migrations must follow expand-migrate-contract.
* API changes must be backward-compatible within the documented compatibility window.
* Use structured logs and correlation identifiers.
* Add OpenTelemetry traces and Prometheus metrics to every service.
* Avoid unnecessary abstractions, but do not couple domain logic to infrastructure providers.
* Do not suppress type, lint, test or security failures without documented justification.
* Do not delete or weaken existing tests to make the build pass.
* Do not add TODO placeholders for mandatory requirements.
* Do not use mutable production image tags.
